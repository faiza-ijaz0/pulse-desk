# Testing Strategy

Goal: catch regressions where they're cheapest to catch. Most tests are unit tests.
Tenant isolation and auth are covered with real database integration tests, and
critical user journeys are covered end-to-end.

## Test layers

| Layer               | Tool                                     | Location                                                      | Runs against                                                                             | Covers                                                                                                                                      |
| ------------------- | ---------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **Unit**            | Vitest                                   | `*.test.ts` beside source; `apps/api/test/*.test.ts`          | Pure functions, injected deps and in-memory repositories                                 | Zod contracts, permissions, lifecycle and SLA math, env validation, middleware, SLA and auto-close sweeps (fake clock), scheduler, shutdown |
| **Component**       | Vitest + React Testing Library + `jsdom` | `apps/web/src/**/*.test.tsx`                                  | Rendered components; `fetch` stubbed per path (`apps/web/src/test/render.tsx`)           | Accessible queries (`getByRole`), forms, keyboard interaction, loading/error/empty states, theme toggling                                   |
| **API integration** | Vitest + Supertest                       | `apps/api/test/integration/*.int.test.ts`, `packages/db/test` | Real Express app, **real PostgreSQL** (`TEST_DATABASE_URL`)                              | Routing, validation, auth/session flows, RBAC, **cross-tenant isolation**, error shapes, rate limits, sweeps, migrations                    |
| **End-to-end**      | Playwright + `@axe-core/playwright`      | `e2e/tests/**/*.spec.ts`                                      | Production builds of web + API (sweeps off under `NODE_ENV=test`), proxy secret enforced | Sign-up/sign-in, tickets, directory and settings, SLA, members and invitations, axe WCAG 2.2 AA scans in both themes                        |

## Rules

1. **Never mock the database in integration tests.** Isolation guarantees come from real
   constraints, which mocks can't verify.
2. **Every tenant-scoped endpoint has a cross-tenant test** (see
   [data-model.md](./architecture/data-model.md#layer-4--tests-that-try-to-break-it)).
3. **Every permission rule has an allow test and a deny test.**
4. **Time is injected.** SLA tests use a fake `Clock`, never real timers or `sleep`.
5. **Tests are independent.** The test database is reset once per run; each test then builds
   its own data in fresh organizations with helpers (`registerOwner()`, `addMember()`,
   `uniqueEmail()`), not shared fixtures.
6. **Accessible queries first.** Component tests use `getByRole` / `getByLabelText`. `data-testid` is a last resort.
7. **E2E stays small and stable.** Only critical journeys. No arbitrary waits; use web-first assertions.

## Test database lifecycle

```
pnpm test:integration (Vitest "integration" projects in packages/db, then apps/api)
 └─ globalSetup: refuse to run unless the test database passes the safety check below,
    then `prisma migrate reset --force` — applies the committed migration SQL from scratch
    (shared helper: `@pulsedesk/db/testing`)
     └─ tests create uniquely-named organizations and clean up after themselves
```

A missing test database is a **failure**, never a silent skip. Integration files run
serially (one database); unit and component tests run in parallel.

**Which database may be wiped.** `assertSafeTestDatabase`
(`packages/db/src/test-database-target.ts`) runs on the final environment (shell variables
win over `.env`) before Prisma or any test connects. It is used by the integration reset,
by both packages' test helpers, and by `e2e/playwright.config.ts` before any server starts. It
refuses, without printing credentials, unless:

- `TEST_DATABASE_URL` is a `postgresql://` URL naming exactly the database `pulsedesk_test`;
- its host is this machine (`localhost`, `127.0.0.1` or `::1`) — no remote host is allowed,
  whatever the database is called;
- it isn't the development database: host (local spellings count as one), port and database
  name are compared after parsing, so usernames, query strings and percent-encoding can't make
  them look different;
- neither URL uses query parameters that redirect the connection (`host`, `port`, `dbname`,
  `service`, …), and the test URL uses only harmless ones (`schema`, `sslmode`, timeouts…);
- both URLs state their port (clients would otherwise fill it from `PGPORT`) and neither
  hostname is percent-encoded (`pg` decodes `%6Cocalhost` to `localhost`).

`DATABASE_URL` is required for the integration reset. E2E compares it only when it is set,
because CI's E2E job has no development database.

`packages/db/test/migration-upgrade.int.test.ts` runs migrations inside a transaction it
always rolls back. Before it does, `assertSafeInTransaction`
(`packages/db/src/migration-sql-guard.ts`) refuses migration SQL that could end or break
that transaction: transaction control, `CONCURRENTLY`, `VACUUM`, `SET`/`search_path`
changes, names qualified with `public`, `dblink`, dynamic SQL and similar. It is a
conservative scanner (comments, strings and quoted names are skipped), not a full SQL
parser: anything it can't scan is refused, and a refusal means "check by hand".

## Coverage

Coverage will be collected with `@vitest/coverage-v8` once business modules exist. It is a
signal, not a target. The planned floor (80% lines) applies to `apps/api/src/modules/**`
services and policies, where business rules live. UI coverage is judged by meaningful
component tests, not percentages.

## Continuous integration

`.github/workflows/ci.yml` runs on every push to `main` and every pull request:

1. **verify** — frozen-lockfile install → format check → lint → typecheck → unit/component
   tests → database integration tests (PostgreSQL 17 service container) → `db:deploy` and
   `db:seed` (twice, proving it is repeatable) against a separate application database →
   production builds.
2. **e2e** — after `verify` passes, with its own PostgreSQL service: build → Playwright
   (Chromium; migrates the database, then signs up a user once and reuses its session) →
   HTML report uploaded on failure.

The service container creates only `pulsedesk_test` (`POSTGRES_DB`); the workflow creates the
`pulsedesk` application database with `createdb` before migrating it, so `DATABASE_URL` and
`TEST_DATABASE_URL` always point at two real, distinct databases. Runners are pinned to
`ubuntu-24.04` so image upgrades are deliberate.

**E2E servers are never reused.** `pnpm test:e2e` always starts its own API (`:4100`, on
`TEST_DATABASE_URL`, with a throwaway proxy secret) and `vite preview` (`:4173`). If either
port is already taken — e.g. by a `vite preview` you left running — Playwright stops with
"… is already used …": stop that process (check IPv6 `[::1]` too; on Windows
`Get-NetTCPConnection -LocalPort 4100,4173 -State Listen`). Before signing up, the setup
project checks that `/health` through the preview reports the E2E API's version, so a
preview proxying anywhere else fails with that diagnosis instead of a signup error.

**AI coding agents:** Prisma 7 refuses `prisma migrate reset` (used by the integration
setup) when it detects an AI agent, until the user explicitly consents. It is passed by
setting `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` to the user's consent message. Grant it
only for disposable databases.

Real-time (Socket.IO) and queue tests, and a Redis CI service, will be added with those features (planned).
